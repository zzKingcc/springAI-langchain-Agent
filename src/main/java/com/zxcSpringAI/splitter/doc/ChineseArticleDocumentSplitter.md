# ChineseArticleDocumentSplitter 工作原理

## 核心策略

**章节感知 + 超长兜底**：不是按固定字符数盲切，而是先识别文章自然章节边界，再对超长章节做子切分。

---

## 切分流程

```
原始文本
  │
  ▼
第一层：章节标题识别（9 类正则）
  │
  ▼
第二层：章节级切分（按标题边界语义切分）
  │
  ▼
第三层：超长章节兜底（>600 字符，recursive splitter）
  │
  ▼
第四层：元数据注入（file_name + section_title）
```

---

## 第一层：章节标题识别

逐行扫描文档，用正则匹配标题行，覆盖 9 种中文编号形式：

| # | 形式 | 示例 |
|---|------|------|
| 1 | 中文大写数字 + 顿号/点 | `一、` `三．` `十二、` |
| 2 | "第X章/节/条/篇/步/款/部分/轮" | `第一章` `第三步` `第二条` |
| 3 | 阿拉伯数字编号 | `1.` `2.3` `4.5.6` |
| 4 | 圆括号编号 | `(1)` `(三)` `(十二)` |
| 5 | 圆圈数字 Unicode | `①` `②` `⑪` |
| 6 | 方括号关键字 | `【摘要】` `【结论】` `[一]` |
| 7 | 大写字母 + 点 | `A.` `B、` |
| 8 | Markdown 标题 | `##` `###` |
| 9 | 附录/附表/附图前缀 | `附录A` `附表 3` |

### 双重校验防误判

正则匹配后，跳过编号前缀（如 `1.2.3`、`第X章`），检查剩余正文文字是否 ≥ 2 个字符，避免 `1.` 或 `## ` 这种空标题行被误识别。

---

## 第二层：章节级切分

按标题边界进行语义切分，保证每个章节是一个**语义完整的段落群**，不会在句子中间切断。

```
逐行扫描文档
  │
  ├── 遇到标题行 → flush 前一章节 → 开启新章节（标题作为 section_title）
  │
  └── 普通行 → 追加到当前章节缓冲区
  │
最后 flush 收尾
```

---

## 第三层：超长章节兜底

```java
if (章节字符数 > 600) {
    // 委托给 LangChain4j 内置 recursive splitter
    // 递归降级：段落 → 句子 → 字符
    // 子段间保留 80 字符 overlap
    fallbackSplitter.split(sectionDoc);
}
```

- **短章节（≤600 字符）**：直接产出 1 个 TextSegment
- **长章节（>600 字符）**：按 `段落→句子→字符` 逐级降级切分

### 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| maxSegmentLength | 600 | 单段最大字符数 |
| maxOverlapLength | 80 | 子段间重叠字符数 |

---

## 第四层：元数据注入

每个产出的 TextSegment 都携带元数据：

| 字段 | 来源 | 用途 |
|------|------|------|
| `file_name` | 来源文件名 | 区分不同文档的片段 |
| `section_title` | 所属章节标题 | 检索命中时帮助模型理解上下文位置 |

这些元数据会随片段一并存入向量库和 ES，在召回后用于：
- 交叉验证的重排序 boost（标题命中加权）
- 引用溯源（告诉用户答案来自哪个章节）

---

## 设计优点

1. **语义完整性优先**：短章节不切分，保持段落群完整
2. **自然边界感知**：9 类标题正则覆盖绝大多数中文文档的编号习惯
3. **超长兜底**：极端长章节不会因字符超限而截断中间句子
4. **可配置**：`maxSegmentLength` 和 `maxOverlapLength` 支持外部注入
5. **结构保留**：通过 `section_title` 保留原文的层级结构信息
